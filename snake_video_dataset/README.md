# Snake video frame candidate pipeline

Original videos stay in `source_videos/` unchanged. The existing `metadata/global_video_manifest.csv` supplies labels only when its verification status is `VERIFIED`; filenames and folders never verify a label. Missing labels remain `UNKNOWN` and every selected frame starts as `REVIEW_REQUIRED`.

Run `python snake_video_dataset/scripts/extract_video_frames.py` from the project root. It writes `video_dataset_candidate_v1/video_manifest.csv`, `review_index.csv`, selected JPEG frames, `audit_report.json`, and `dataset_fingerprint.sha256`. The default interval is 2 seconds. Alternatives: `--method fps --target-fps 1` and `--method motion --min-frame-change 9 --min-seconds 0.5 --max-seconds 4`. Motion change is mean absolute difference on resized grayscale images; duplicates use the same 64 × 64 image difference against the last retained frame. `--dry-run` computes an audit without writing. `--input` accepts a directory or one video; `--source`, `--label`, and `--group-id` override metadata for one input, with labels remaining provisional.

Quality checks reject only near-black and severely overexposed frames. Very low detail or blur is flagged for review. Thresholds are CLI options. Decode failures are counted in the video manifest. The review index records each sampled frame, including rejected and duplicate decisions. Selected JPEGs require manual label and image review before any training use. Record decisions in a separate CSV with columns `video_id,frame_number,review_status,verified_label,verification_note`. Only `APPROVED` decisions with a verified snake class and an evidence note can enter the admission manifest via `python snake_video_dataset/scripts/finalize_review.py --decisions path/to/decisions.csv`. This verifies frame hashes and group splits. No frames are automatically copied into `clean_dataset`.

For multiple clips from one recording or rescue event, add `metadata/group_overrides.csv` with columns `relative_path,group_id`, using paths relative to `snake_video_dataset/`. All clips with one group ID receive one split. Pre-existing source-group IDs are scoped by source category to avoid collisions. Unknown or mixed-label groups remain unassigned. A validation group is reserved only after five independent verified groups per class, and a video test group only after eight. This does not alter the frozen image test set. Check recording origins and override groups before using any split for evaluation.

The candidate fingerprint hashes the canonical video and frame manifests, including original video and saved frame SHA-256 values. An initial candidate has zero admitted training frames because review is pending. After reviews or group corrections, regenerate the candidate and fingerprint as a new version; do not silently edit an already used candidate.

Framewise training later treats selected frames as individual image samples. It can improve robustness to changing snake appearance, pose, visibility, backgrounds, lighting, and camera distance. MobileNetV3 Large does **not** learn temporal motion patterns from these isolated images; sequence modeling would be a separate future experiment. Any eventual training experiment must preserve the seven-class order and benchmark all wildlife classes against the existing frozen image test set, with video groups kept apart for validation and video testing.

## Manual review preparation

Run `python snake_video_dataset/scripts/prepare_manual_review.py` once for an extraction candidate. It writes `video_label_audit.csv` (one row for every video), `proposed_group_review.csv`, `review_worklist.csv`, `video_label_decisions_template.csv`, and video-organized `contact_sheets/`. The worklist has a stable `review_id` of `video_id:frame_number`, the frame path and timestamp, source/group/split, original label and quality decisions, plus editable `review_status`, `verified_class`, `species_name`, `rejection_reason`, `review_notes`, and `verification_note`. Every frame starts `REVIEW_REQUIRED`. Source-verified class labels are carried into `verified_class` as label metadata only; this does not approve a frame. Unknown videos keep `UNKNOWN`. Keep a separate copy of an edited worklist because rerunning preparation overwrites the generated template.

Use the contact sheets to inspect snake visibility and image usability. Confirm uncertain video labels and related recording groups with the source owner. To apply a manually confirmed class across one video's worklist rows, edit a copy of `video_label_decisions_template.csv` with a snake class and `verification_note`, then run `python snake_video_dataset/scripts/apply_video_labels.py --decisions path/to/video_decisions.csv --worklist path/to/current_worklist.csv --output path/to/labeled_worklist.csv`. This changes labels and optional species metadata; it preserves every frame's review status. Do not treat an unverified filename as confirmation.

Mark each frame `APPROVED`, `REJECTED`, or `REVIEW_REQUIRED` independently. An approved frame needs a verified snake class and evidence note; a rejected frame may record `rejection_reason` and `review_notes`. Run `python snake_video_dataset/scripts/review_summary.py --worklist path/to/edited_worklist.csv` to see class, video, group, source, split and unresolved-label counts. `finalize_review.py --decisions path/to/edited_worklist.csv` validates approved frame hashes and writes a separate admission manifest. An approved row may still have `UNASSIGNED_REVIEW` as its provisional split: approval is **not** permission to train or merge datasets. Final group-aware splits are deferred until labels, usable frame counts and source relationships are resolved.

## Local frame reviewer for source-verified videos

Launch `python snake_video_dataset/scripts/manual_frame_reviewer.py` from the project root. The Tkinter reviewer opens only frames from the 18 videos marked `SOURCE_VERIFIED` in `video_label_audit.csv` (281 frames: 191 venomous and 90 nonvenomous). The verified class is shown read-only; there is no model inference. Each frame appears at a time with video and frame metadata, progress, and approved/rejected/remaining counts. Use large APPROVE, REJECT, PREVIOUS, NEXT, and UNDO buttons, or `A`, `R`, left/right arrows, and `U`. The optional rejection-reason menu includes snake not visible, unusable blur, corruption, scene transition, and other. Class and video-ID filters only change navigation.

On first launch the reviewer creates `video_dataset_candidate_v1/review_worklist_manual.csv` as a separate copy of the original worklist; every human decision is saved immediately using a temporary file and atomic replacement. Subsequent launches resume at the first `REVIEW_REQUIRED` frame, while previous and next navigation can revisit completed decisions. The original `review_worklist.csv` and extracted JPEGs stay unchanged. The manual CSV retains the 44 unverified videos without displaying them, so the existing summary and finalization tools can read it. Run `python snake_video_dataset/scripts/manual_frame_reviewer.py --self-test` for headless loading and temporary save/resume validation; it creates no real decisions.
